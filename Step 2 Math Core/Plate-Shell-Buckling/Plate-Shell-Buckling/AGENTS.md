# Plate–Shell Buckling 资料包工作规则

在本目录回答问题、修改公式、设计测试或连接求解器前：

1. 先读 `AI_CONTENT_INDEX.json`，路由到最小相关文件。
2. 再读 `AI_USAGE.md`，确认符号、分析层级和禁止推断。
3. 把 `01_核心算法/核心算法与实现顺序.md` 视为本包算法契约；完整推导以 `04_完整参考/` 为准。
4. 每次报告都声明所处层级：LBA、GNA、GNIA 或 GMNIA。不得只写“buckling analysis”。
5. 若使用 `K_T = K_M + K_σ`，压缩对应的 `K_σ` 通常为削弱项；若使用 `K_M φ = λK_G φ`，则明确 `K_G = -K_σ,ref`。不得混用两套正号。
6. 几何刚度必须来自已经平衡的预屈曲应力状态，并保留参考载荷、单位、局部坐标和载荷路径。
7. 模态必须记录特征值、归一化方式、符号、几何自由度筛选、重根/近重根处理和网格版本。模态幅值本身没有物理长度。
8. 初始缺陷必须记录来源、幅值单位、归一化、正负号和应用后的几何核对；不得把任意特征向量直接加到节点坐标。
9. 线性特征值只表示完美基本路径上的局部中性点。不得把它称为实际极限载重、试验强度或设计强度。
10. 后屈曲必须至少报告控制方法、步长、残量、切线/最低特征值历程、分支选择和缺陷定义。
11. 修改核心公式或验证阈值时，至少运行 V10–V18；涉及缺陷或路径跟踪时再运行 V19–V22。
12. 新增公式、基准或容差时，记录来源、页码、单位、边界条件、适用范围和配对验收标准。
13. 包内答案是理论/解析参考，不是某个实现已经通过的证据。实际通过必须附运行记录和版本信息。
14. `06_生成脚本/` 是来源副本；修改或运行前先阅读其 README，不得假定所有依赖已随包迁移。
