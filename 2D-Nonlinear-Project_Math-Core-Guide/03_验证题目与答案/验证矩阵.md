# 2D-Nonlinear-Project 验证矩阵

## 1. 分层顺序

固定顺序为：符号与客观性 -> 线性恢复 -> 局部/装配切线 -> Newton 路径 -> 控制方式 -> 状态事务 -> 弧长 -> 二维模型集成。前一层失败时，后一层“曲线看起来合理”不能作为补偿。

## 3. 建议自动化元数据

每次测试至少保存：

- 模型、网格、材料、边界和单位；
- 残量符号与切线定义；
- 控制方式和控制自由度；
- 步长、弧长、`beta`、线搜索参数；
- 绝对/相对/能量容差和 floor；
- 每次迭代的残量、修正、线性残差和接受的 `alpha`；
- 每步 trial/commit/rollback 事件；
- `detJ0`、`detF`、材料局部积分状态；
- 参考值、来源页和误差；
- 软件版本、提交或模型哈希。

## 4. 方向导数的标准执行方式

1. 固定同一个 committed state；
2. 选择非零随机方向并归一化；
3. 分别在 `u+h*p` 与 `u-h*p` 从同一 committed state 重算试算响应；
4. 扫描多个 `h`；
5. 比较 `K_t*p` 与中心差分；
6. 分别报告内力切线、外力切线和总有效切线；
7. 若模型非光滑，记录激活集变化并改用分段验证。

## 5. 步长与控制回归

至少保留三类路径：

- 稳定单调段：荷载、位移、弧长应重合；
- 荷载极限点：荷载控制作为预期失败对照，位移/弧长继续；
- snap-back：选定单一位移控制作为预期失败对照，弧长继续。

至少使用三档步长；若峰值、耗散或路径随步长显著变化，应继续细化或报告未收敛。

## 6. 可合并门槛

数学核心改动只有在以下条件同时满足时，才可视为未退化：

1. V00-V08 全部通过；
2. V02 不得通过放宽到无法区分错误切线的容差；
3. V07 的失败试算不会改变 committed state，restart 结果一致；
4. 若改动影响控制或约束，必须运行 V04-V08；
5. 若改动影响元素/材料接口，必须运行 V00、V02、V07、V09；
6. 若存在极限点声明，必须保存路径和控制失败对照；
7. 失败必须分类为模型、控制、切线、状态、线性代数或容差问题；
8. 不得只凭“最终结果接近”删除迭代历史或失败证据。
