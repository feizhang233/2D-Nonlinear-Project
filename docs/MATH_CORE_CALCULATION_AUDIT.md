## 4. V03 符号说明

V03 题面单独写成：

```text
R = f_int - f_ext
Delta theta = -R / K
```

项目全局统一约定为：

```text
r = f_ext - f_int
K * Delta theta = r
```

所以项目迭代记录中的 `r` 与 V03 表中的 `R` 数值绝对值相同、符号相反。审计报告在与
配套答案比较前显式执行 `R=-r`；四次 `theta/R/K` 历史与独立公式逐位一致。这一展示
差异不能通过修改求解器符号“修复”，否则 V01 会立即失败。

## 5. V04 与 V09 离散偏差

V04 解析极限荷载为 `7.75287283030`，20 个弧长接受步采样到的最大值为
`7.74590917445`，相对差 `0.0898%`。原因是数值路径点没有恰好落在解析峰值，不是平衡
残量偏差；路径已经越过 `v*=2.62765`，末点荷载降至 `3.14892`。

真实 Frame 浅拱用位移增量 `0.02/0.01/0.005` 得到的离散峰值分别为
`295.2888/295.5252/296.2416 N`，总跨度 `0.9528 N`，约为峰值的 `0.32%`。峰值是离散
步点的最大值，步点相位会影响是否落在峰顶附近；当前跨度低于验证矩阵采用的 `1 N`
门槛。若后续需要把极限荷载作为工程报告值，应对峰值附近自适应细分或用一致的极限点
定位器，而不是直接把离散最大点当作精确峰值。

## 6. 重大问题判定与处理

本次把以下情况视为重大问题：V00-V08 任一题不通过；V02 没有内部误差谷；V07 失败
试算污染提交状态；稳定段三种控制不重合；极限点失败未分类或回滚边界丢失；步长或网格
结果超过既有精度预算。实际结果均未触发这些条件，因此没有修改数学核心实现，也没有
放宽任何已有容差。

新增的是可复现审计基础设施：脚本会重新调用当前公开求解器/单元接口，生成 JSON，并在
结果失败或已检入证据过期时返回非零退出码。
